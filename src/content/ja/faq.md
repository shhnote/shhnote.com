<div class="faq">
  <details open>
    <summary>アカウントは必要ですか？</summary>
    <p>いいえ。登録もインストールも不要です。shhnote を開いて、シークレットを書き、リンクを共有する。それだけです。</p>
  </details>
  <details>
    <summary>意図しない人にリンクを見られたら？</summary>
    <p>1回限りのシークレットを読めるのは、最初に開いた1人だけです。その後は破棄されるため、本来の受信者が開いたときに何も見つからなければ、誰かが先に読んだと分かります。さらに安全にしたい場合は、パスフレーズを追加して別の手段で伝えれば、リンクだけでは開けなくなります。気が変わったときは、自分専用の破棄リンクでシークレットを自分で破棄することもできます。</p>
  </details>
  <details>
    <summary>shhnote は私のシークレットを読めますか？</summary>
    <p>いいえ。シークレットを開く鍵は私たちに届きません。鍵はあなたの手元にあるリンクの中に収まっています。私たちが保持しているのは、開く手段のない暗号化されたデータだけです。</p>
  </details>
  <details>
    <summary>誰も開かなかった場合はどうなりますか？</summary>
    <p>有効期限は15分から14日の間で選べます。期限が来ると、開かれたかどうかにかかわらず、シークレットは自動的に削除されます。</p>
  </details>
  <details>
    <summary>1回限りのシークレットと期限付きのシークレットの違いは？</summary>
    <p>1回限りのシークレットは、開いた瞬間に破棄されます。期限付きのシークレットは、有効期限が来るまで何度でも開けます。ただし、残り時間はページに表示されないので、どのシークレットも最初に読んだときに保存するようにしてください。</p>
  </details>
  <details>
    <summary>破棄リンクとは何ですか？</summary>
    <p>シークレットを作成したときに受け取る、2つ目の自分専用のリンクです。開くと確認画面が表示され、確定すると、誰かが読む前にシークレットがすぐに破棄されます。他の人には渡さないでください。</p>
  </details>
  <details>
    <summary>ファイルも送れますか？</summary>
    <p>はい。ファイルもテキストとまったく同じようにブラウザ内で暗号化され、同じ封印されたデータの中に入って送られます。すべて標準的なサイズにパディングされるため、短いメモか小さなファイルかは私たちにも区別できません。</p>
  </details>
  <details>
    <summary>Tor Browser や JavaScript をオフにした状態でも使えますか？</summary>
    <p>暗号化はブラウザ内で行われるため、シークレットの作成と表示には JavaScript が必要です。Tor Browser の「より安全」レベルでは動作します。「最も安全」では WebAssembly が無効になるため、パスフレーズで保護されたシークレットは開けず、ページにその旨が表示されます。それ以外のページはすべて JavaScript なしで動作します。</p>
  </details>
  <details>
    <summary>1回限りの保証は、競合状態に対してどのように担保されていますか？</summary>
    <p>表示の際には、行を「active」から「claimed」に移す単一の条件付き更新が実行されます。同時に2つのリクエストが来ても、両方が成功することはありません。2つ目のリクエストはすでに claimed になったレコードを見て、他の誰とも同じ「シークレットが見つかりません」という応答を受け取ります。claim が取り消されることはありません。ダウンロードが失敗した場合は、claim トークンの保持者が猶予時間内に再ダウンロードでき、そうでなければシークレットは読まれないまま破棄されます。</p>
  </details>
  <details>
    <summary>なぜクエリパラメーターではなく URL フラグメントなのですか？</summary>
    <p>クエリパラメーターはサーバーに送信され、アクセスログやプロキシ、アクセス解析に残ります。フラグメント（<span class="color-accent">#</span> より後ろ）は、URL の仕様でクライアント側にとどまるよう定められており、ブラウザが HTTP リクエストに含めることはありません。この性質こそが、ゼロ知識設計の土台です。表示後には、ページがアドレスバーと履歴からもフラグメントを削除します。</p>
  </details>
  <details>
    <summary>リンクスキャナーが1回限りのシークレットを先に消費してしまうのを、どう防いでいますか？</summary>
    <p>閲覧ページはどのシークレットでも同じ静的なドキュメントで、読み込み時には何も取得しません。リクエストは、信頼できるクリックまたはキー操作があったときにのみ送信されます。スクリプトによる <code>click()</code> やフォーム送信は対象外です。自動スキャナー（メールのセキュリティ機能、チャットのリンク展開、ウイルス対策ソフト）が読み込むのは、その静的な外枠だけです。</p>
  </details>
  <details>
    <summary>検証したり、セルフホストしたりできますか？</summary>
    <p>はい。ソースコードはすべて AGPLv3 のもとで公開されています。プロトコルは仕様書にまとめられており、どの実装でも自己検証できる適合性テストベクターが用意されています。セルフホスティングガイドもあります。クライアント側の暗号処理を監査し、自分のインスタンスを運用すれば、信頼の境界を完全に自分の手元に置けます。</p>
  </details>
  <details>
    <summary>不正利用の防止のために何か記録していますか？</summary>
    <p>シークレットごとのアクセスログや IP の履歴は残していません。レート制限には、定期的に入れ替わるソルトを用いたアドレスの鍵付きハッシュを使っており、ソルトが入れ替わるとすべてのカウンターも消去されます。不正利用の通報は1日ごとの件数として数えるだけで、どのシークレットが通報されたかの記録はありません。</p>
  </details>
  <details>
    <summary>API はありますか？</summary>
    <p>はい。このサイト自身が使っているものと同じ API です。<a href="/en/docs/">ドキュメント</a>で説明しています。オープンソースのクライアントパッケージはこのプロトコルを実装しているので、独自のツールに組み込めます。</p>
  </details>
